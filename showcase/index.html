案例 01

从一条真实学习记录创建作品

解决素材、选题和稿件彼此割裂，创作时反复寻找上下文的问题。

输入

素材：第一次独立定位 Python 项目启动错误；状态：用户已亲测；待补：复现步骤截图。

保存结果

1 个作品 · 2 种内容形式 · 1 份定位快照

从素材创建作品，同时选择“图文”和“录屏教程”；作品保存创建时的定位快照，后续修改账号定位不会改写旧作品。

系统处理

  1. 关联有来源状态的素材
  2. 创建选题与作品记录
  3. 保存形式和定位快照
边界处理

尚未完成的截图会保留为“待补”，不会被写成已经亲测的结果。

IMPLEMENTATION

技术方案

应用层Python · FastAPI · 原生 HTML/CSS/JS

本机 Web 应用，无前端构建依赖。

数据层SQLite · 版本快照 · 幂等写入

保存创作资料、稿件版本、任务和复盘。

AI 层DeepSeek API · 结构化输出

模型失败时保留已有稿件，并隐藏服务商原始错误。

质量层pytest · Playwright

验证后端行为、真实按钮、刷新持久化和移动端布局。
