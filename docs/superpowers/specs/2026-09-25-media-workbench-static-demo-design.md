# 自媒体内容创作工作台静态演示设计

## 目标

为现有 `media-topic-assistant` 公开仓库增加无需后端、密钥或登录即可访问的项目介绍与交互演示页，并部署到 GitHub Pages。作品集项目卡片改为指向该演示页。

## 展示边界

- 页面明确标注为静态流程演示，不调用 DeepSeek，不读写访客数据，也不模拟平台发布。
- 文案只采用仓库 README、验收文档和自动化测试可核验的能力。
- 不展示本机数据库、真实 API 密钥、个人素材或测试截图中的隐私数据。
- 正式应用仍是本机 FastAPI + SQLite 工作台；静态页只负责介绍和演示。

## 页面结构

1. 首屏：项目定位、查看演示、查看源码和静态边界说明。
2. 工作流：定位 → 素材 → 选题 → 策划/稿件 → 制作排期 → 发布登记 → 复盘。
3. 三个可切换案例：素材变作品、版本与制作、发布与复盘；每个案例展示输入、系统处理、保存结果和解决的问题。
4. 可核验数字：8 个助手、5 种内容形式、75 项后端自动化测试、390px 移动端浏览器覆盖。
5. 技术实现：Python、FastAPI、SQLite、DeepSeek API、原生 HTML/CSS/JS、pytest/Playwright。

## 视觉与交互

沿用现有工作台的米白、墨绿和橙色视觉语言。页面使用本地 CSS/JS，不依赖 CDN；移动端无横向溢出；案例按钮支持鼠标和键盘顺序访问。禁用 JavaScript 时仍能看到项目定位、工作流、指标和首个案例。

## 发布与验收

- `showcase/` 存放静态站点，GitHub Actions 从 `main` 自动部署。
- 线上地址为 `https://kexinyang74-web.github.io/media-topic-assistant/`。
- 验收包括静态结构测试、交互逻辑测试、现有后端测试、浏览器视口检查、Pages 工作流和线上 HTTP/内容检查。
